# Hero Choreography & Storyboarding

## Hero is OPTIONAL

A cinematic Hero is not required for Apple-quality design. A strong static composition may be the better design.

## When a Hero IS justified

- The product benefits from dominant establishing visual moment.
- The user task benefits from a memorable first impression.
- The story / narrative benefits from a cinematic opening.
- Real assets support the chosen cinematic treatment.

## Hero Choreography Brief

Before implementing a complex Hero, establish:

- **Subject** — main subject.
- **Start state** — opening visual.
- **End state** — closing visual of the Hero.
- **Transition into next experience area** — how the Hero yields.
- **Required beats** — must-have moments.
- **Preferred beats** — desired moments.
- **Optional polish** — nice-to-have.

If the user has not specified choreography and the project requires a complex Hero, ASK.

## If the user does not know the choreography

Do not demand cinematography expertise. Offer a small set of asset-feasible conceptual routes:

- restrained product approach
- partial product reveal
- detail transition
- multi-shot feature sequence
- product-to-interface transition

Then let the user choose / modify.

## Visual Beats (Skill vocabulary)

Convert the user's natural-language choreography into Visual Beats. A Beat answers:

- **Subject**
- **Start state**
- **End state**
- **Visual intent**
- **Required media**
- **Feasibility**

State describes what the resulting picture should communicate, not implementation technology.

## Hero State Graph (Skill vocabulary)

```
Establish
   ↓
Transform / Reveal
   ↓
Focus
   ↓
Inspect / Emphasize
   ↓
Transition
```

Exact states vary by project. Do not force this sequence universally. The important concept: **Hero = multiple meaningful visual states**, not one "hero image."

## Storyboard before timeline

Hard order:

```
Intent
↓
Visual Beats
↓
Visual States
↓
Feasibility
↓
Storyboard
↓
Transitions
↓
ONLY THEN
scroll / time percentages
```

Do NOT begin with arbitrary "0–20% rotate, 20–40% zoom…" before the visual story and assets are established.

Any percentages / timing are implementation heuristics. Never Apple canonical values.
